# 뛸까말까 🏃🏻
현위치에서 역까지 도보 거리 + 실시간 지하철 도착 정보로 지금 뛰어가면 탈 수 있나를 판정한다.

## 동기
아침에 급한 상황에서 지도 어플을 통해 검색해서 열차 확인 후 내 남은 거리를 생각하며 뛸지 말지 결정하기 불편했다. 매일 같은 상황인데 그냥 켜자마자 확인할 수는 없을까? 에서 시작되었다.

## 설계 결정
- nextjs 사용. 서울시 실시간 지하철 도착정보 API가 http로 되어있어 http로 된 사이트에 요청을 해야하고 api키를 보관하여야 하여 SSR이 필요하다고 판단하였다. 또한 랜더링 속도를 높이기 위해 SSG도 필요하였다.  
- tanstack query 사용. 5~20초마다 도착 정보가 클라이언트 측에 갱신되어야 하는데 setInterval로 router.refresh()로 하면 도착 정보 뿐만 아니라 서버 컴포넌트 전체를 다시 랜더링 해야해서 무겁다. 또한 여러 상태와 재요청 등을 직접 관리하려면 복잡도가 올라간다. --> SWR이 더 나을지도..

## 문제 해결
- 사용자가 위치 허용을 안 할 수 있음 --> 걸리는 시간을 직접 입력 받곡 그 값을 localstorage에 저장 후 그 역 선택 시 디폴트로 함  
- 실시간 지하철 API에서 barvlDt(열차 도착까지의 예상 잔여시간)가 같은 구간에서 동일한 값으로 유지된다(2026-10-29 15:36-16:13 11개 역을 20초 간격으로 25분 연속 수집, 서울시 API 875회 호출 결과 barvlDt는 열차가 한 구간에 있는 동안 같은 값으로 고정돼 있음 1,3,4,9호선은 100% 그대로 그런데 recptnDt는 21~27초마다 새로 찍힘 --> recptnDt + barvlDt가 갱신될 때마다 뒤로 밀림 --> 예측이 계속 늦어짐 --> **같은 열차의 barvlDt가 새 값으로 바뀐 첫 응답에서 도착 시각을 계산해 고정하고 값이 그대로면 고정한 시각을 유지** --> 그 결과 적중률이 47%에서 78%로 올라갔다, 평균 내기 같은 방법은 68% ~ 75%로 이 규칙보다 못 함)
남은 한계: 앱을 막 열었을 때는 barvlDt가 바뀌는걸 아직 못 봤으니 고정할 수가 없음 --> 이 구간은 62% --> 나중에 데이터베이스에 서울 모든 지하철 정보를 일괄 수집 api로 저장해서 그 값으로 계산
- 8호선, 경의중앙, 수인분당, 신분당 등 9개 노선은 barvlDt가 항상 0이라 남은 시간을 알 수 없음 --> 위치로 추정해보니 적중률 37%라 MVP 목록에서 뺐음
